# VIS007 visibility/excess-private-definitions

A module contains more private definitions than the configured limit.

- **Category:** visibility
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint
- **Automatic fix:** none; repair by hand
- **Guide:** Keep private definitions per module within the limit; split cohesive groups out

## Why

A growing collection of private models and helpers can make a module's responsibility harder to understand. This opt-in review counts private classes, sync/async functions and PEP 695 type aliases directly in a production module body. A leading underscore marks privacy; dunders are excluded. Repeated declarations of the same name and kind, including overloads, count once at their first declaration. Private uppercase assignments with values are listed separately as constants and never contribute to the limit. Imports, ordinary assignment-style type aliases, methods, nested/local definitions and definitions inside control-flow statements are excluded. Package initializers are checked too. A few models beside their consumer remain valid at the default limit of 12. Even a larger cohesive model tree or parser may be intentional: this metric does not infer cohesion, separable groups or safe extraction.

## Bad

```python
# With rules: {visibility/excess-private-definitions: {severity: hint, max: 2}}
class _Cookie: pass
class _StorageItem: pass
def _merge(existing, incoming): ...
class AuthenticationState: ...
```

## Good

```python
# A small local model stays beside its consumer.
class _Cookie: pass
class AuthenticationState: ...
```

## How to fix

Review the listed definitions for a cohesive group that deserves its own module, carrying its constants and validators with it. Choose a name describing that responsibility; models.py is only one possibility. Preserve import direction, initialization, framework registration and module visibility when moving code. Do not make helpers public or extract arbitrary fragments merely to lower the count. Keep deliberate cohesive implementations with a reasoned suppression or package override. No automatic rewrite is performed. Enable rules: {visibility/excess-private-definitions: hint} or select VIS007; set max on the entry, in the root or a style override's rules. The limit defaults to 12; zero is supported.

## Config

- `rules`
- `style.overrides`

Explain it in the terminal with `smelt explain VIS007`.
