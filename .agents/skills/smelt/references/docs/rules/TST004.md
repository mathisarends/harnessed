# TST004 tests/string-patch-target

A recognized patch call or decorator uses a literal string target.

- **Category:** tests
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** error
- **Automatic fix:** none; repair by hand
- **Guide:** Inject fakes or patch objects instead of string targets

## Why

String patch targets encode import paths that refactoring tools may not update. This opt-in convention checks unittest.mock and standard pytest-mock patch, patch.dict and patch.multiple literal targets, plus the dotted-target forms of pytest.MonkeyPatch setattr/delattr. Object/attribute forms are distinguished by their argument shape. It does not claim that object-based patching removes implementation coupling; variables and dynamically computed targets are outside this syntax check.

## Bad

```python
from unittest.mock import patch
@patch("app.service.Repository")
def test_run(repository): ...
```

## Good

```python
def test_run():
    repository = InMemoryRepository()
    run(repository)
    assert repository.saved == [42]
```

## How to fix

Prefer an injected collaborator/fake. For deliberate boundary patching, use object-based patching where appropriate and patch the name looked up by the caller. No automatic rewrite is performed.
