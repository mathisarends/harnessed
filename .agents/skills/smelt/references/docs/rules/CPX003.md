# CPX003 complexity/excess-positional-parameters

A function accepts more positional parameters than its package allows.

- **Category:** complexity
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** warning
- **Automatic fix:** some findings carry a fix
- **Guide:** Keep positional parameters within the package limit; make the rest keyword-only with *

## Why

Call sites such as connect(user, run, tab, True) do not say which value is which, and swapping two arguments of the same type still type-checks. The max of the rule entry is the limit (5 when omitted); parameters after that limit must be keyword-only so every call names them. self and cls are not counted, nor are *args and **kwargs. Dunder methods, @overload and @override definitions are exempt because their signatures are dictated elsewhere, and tests are not checked. Positional-only parameters count like any other positional parameter.

## Bad

```python
def connect(user_id: UUID, run_id: UUID, tab_id: UUID) -> None:
    ...
```

## Good

```python
def connect(user_id: UUID, *, run_id: UUID, tab_id: UUID) -> None:
    ...
```

## How to fix

Insert * after the last allowed positional parameter, then pass the remaining arguments by keyword at every call site. Callbacks whose positional signature is fixed by a framework keep it with a reasoned suppression. Findings carry the * insertion as a suggestion that check --diff --suggestions shows and --fix never applies, because call sites must change too; positional-only parameters and functions with *args get none. Enable it with rules: {complexity/excess-positional-parameters: {severity: warning, max: 3}}; an entry in a style override's rules refines the limit for that package.

## Config

- `rules`
- `style.overrides`

Explain it in the terminal with `smelt explain CPX003`.
