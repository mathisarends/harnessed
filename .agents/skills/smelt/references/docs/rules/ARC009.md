# ARC009 architecture/member-boundary

A workspace member imports a member outside its may_depend_on allowlist.

- **Category:** architecture
- **Activation:** explicit — Enable by rule setting or --select; requires that architecture.members declares workspace member boundaries.
- **Severity when active:** error
- **Automatic fix:** none; repair by hand
- **Guide:** Import other workspace members only as architecture.members allows

## Why

Member-local layers describe internal design; workspace member boundaries describe which projects may depend on one another. Only direct production imports between discovered members count. Unmatched source members are unrestricted, overlapping source globs combine their allowances, and imports inside one member always pass. Wiring and shared modules retain these boundaries. TYPE_CHECKING follows architecture.import_graph.type_checking; transitive does not apply.

## Bad

```python
# packages/core/src/core/model.py
from api.http import serve
# root policy: architecture.members: {'packages/*': {may_depend_on: []}}
```

## Good

```python
# services/api/src/api/http.py
from core.model import Order
# root policy: architecture.members: {'services/*': {may_depend_on: ['packages/*']}}
```

## How to fix

Move the dependency to an allowed member or invert it behind an interface; change the root allowlist only if the dependency belongs in the intended design.

## Config

- `project.workspace`
- `architecture.members`
- `architecture.import_graph.type_checking`
