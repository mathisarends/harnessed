# VIS010 visibility/test-only-public-attribute

Tests read a public attribute with no observed production access outside its visibility boundary.

- **Category:** visibility
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** warning
- **Automatic fix:** none; repair by hand
- **Guide:** Do not make attributes public only for tests; test observable behavior

## Why

Exposing implementation state just for tests enlarges the apparent API and couples tests to internal representation. This opt-in review covers direct instance assignments in ordinary methods and simple class data declarations on unambiguous top-level classes. Reads by analyzed tests are resolved through known constructors, annotations, fixtures and class aliases/re-exports. The owning class is the default visibility boundary. With public_attribute_boundary set to module, production code in the defining module counts as internal. Any same-named production attribute access outside the boundary, including unresolved receivers and literal reflection, conservatively preserves visibility. Private names, methods/properties, descriptors, decorated/inherited/subclassed classes, slots and custom attribute hooks are excluded. Test-quality exclusions apply to test evidence; test writes alone do not trigger a finding. External consumers and arbitrary dynamic access remain unknown, so renaming requires review. Excluded files (including maintainer scripts), unselected packages and external consumers are unassessed, not proven absent; usage_scope records the configured analysis boundary. Public attributes of classes explicitly exported through __all__ or public package-facade bindings are treated as supported API and retained, including aliased re-export chains.

## Bad

```python
class Worker:
    def __init__(self):
        self.pending = []
    def run(self):
        self.pending.clear()
# tests/test_worker.py
from app.worker import Worker
def test_run():
    worker = Worker()
    worker.run()
    assert worker.pending == []
```

## Good

```python
class Worker:
    def __init__(self):
        self._pending = []
    def run(self):
        self._pending.clear()
        return 'done'
# tests/test_worker.py
from app.worker import Worker
def test_run():
    assert Worker().run() == 'done'
```

## How to fix

Review whether the attribute belongs to the supported API. For internal state, add a leading underscore, update internal references and test observable public behavior. Keep deliberate external or framework contracts with a reasoned suppression. Suggested names avoid observed collisions. Smelt leaves renaming to the caller.
