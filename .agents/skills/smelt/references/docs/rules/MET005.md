# MET005 meta/uncovered-package-facade

A package facade cannot supply names that IMP004 is enabled to check.

- **Category:** meta
- **Activation:** default — Enabled by default.
- **Severity when active:** hint
- **Automatic fix:** none; repair by hand
- **Guide:** Re-export from package facades the names other modules import

## Why

imports/prefer-package-import only reports an implementation import when an ancestor initializer already re-exports every imported name. Where the facade is empty or partial, an enabled IMP004 passes without checking anything. On full checks, this hint counts distinct outside production modules whose effective IMP004 setting is explicit and that import public names from an implementation module that no eligible facade can supply. The evidence goes to the nearest enclosing package with an initializer outside the caller; package-internal, test, initializer, private, star and facade imports do not count, and IMP004 ignore entries exclude their callers. It reports the package once its callers exceed max (default 2). A facade with its own active architecture/missing-facade-export threshold is left to that rule. Changed, staged and path-scoped checks skip this hint.

## Bad

```python
# app/jobs/__init__.py is empty
# app/api.py, app/cli.py and app/web.py each contain:
from app.jobs.worker import start, stop
```

## Good

```python
# app/jobs/__init__.py
from .worker import start, stop

__all__ = ["start", "stop"]
```

## How to fix

Review whether to re-export these names. Re-exports can change import-time behavior. For an intentionally facade-less package, add an ignore entry for MET005 matching the package with a reason.

## Config

- `rules`
- `ignore`

Explain it in the terminal with `smelt explain MET005`.
