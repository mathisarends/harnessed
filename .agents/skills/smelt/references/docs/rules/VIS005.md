# VIS005 visibility/foreign-private-access

Production code uses a private symbol or private attribute owned by another project module.

- **Category:** visibility
- **Activation:** explicit — Enable by rule setting or --select; configurable when style or a package override sets private_attribute_boundary.
- **Severity when active:** warning
- **Automatic fix:** none; repair by hand
- **Guide:** Use only your own module's private names; expose a public operation instead

## Why

A leading underscore marks a name as private to its owner. Reaching into a collaborator's private helpers, fields or methods couples the caller to implementation details. This opt-in review reports two kinds of access. symbol: relative and absolute from-imports and module-qualified reads of a module-level private name, through lexical import aliases, when it statically resolves to a definition in another analyzed production module, including sibling modules of the same package. Public aliases remain public, and a package initializer may re-export its own submodule's private symbol under a public alias. TYPE_CHECKING follows architecture.import_graph.type_checking. attribute: reads, writes, calls, updates and deletes of a private member, such as self.log._images, whose receiver and defining project class are statically known and live in another module, or another package under style.private_attribute_boundary: package. Direct accesses on the method receiver to its own or inherited members are allowed. Receiver evidence comes from parameter/variable annotations, direct constructor assignments, stable local aliases, class/instance fields, property return annotations and bounded single inheritance; import aliases, relative imports and static facade re-exports resolve to the defining class. Unlike Ruff SLF001, unresolved receivers are not reported. Dunders, third-party and unknown names, private module names, reflection, same-module access, unknown factories, inherited lookup across multiple/unknown bases, arbitrary class decorators, local imports in attribute evidence, comprehension/lambda receiver bodies, closure/global-variable flow, rebound or shadowed bindings and wildcard imports are skipped. Tests are covered by tests/private-access (TST002). No control-flow narrowing, runtime dispatch or analyzed code execution is used.

## Bad

```python
# app/client.py
from app.session import SessionLog
from .service import _normalize
def persist(log: SessionLog):
    return _normalize(log._images.retain())
```

## Good

```python
# app/client.py
from app.session import SessionLog
from .service import normalize
def persist(log: SessionLog):
    return normalize(log.retain_images())
```

## How to fix

Give a shared helper a module-public name, keeping it out of __all__ and the package facade when it is internal to the package, or move it into the module that uses it. For attributes, expose a meaningful operation on the owning class or pass a deliberate public dependency; do not merely rename or wrap internal state to silence the report. Preserve evaluation order, exceptions and side effects. No automatic rewrite is performed. Enable rules: {visibility/foreign-private-access: warning}, select VIS005, or set private_attribute_boundary under style or in a style override. The boundary defaults to module; package permits attribute cooperation between modules of the same immediate Python package and does not relax private symbols. Reasoned suppressions on the imported name, read or attribute are supported.
