# TYP002 typing/redundant-future-annotations

Review an annotations future import with no detected postponement need.

- **Category:** typing
- **Activation:** explicit — Enable by rule setting or --select; requires that style or a package override sets future_annotations to when-needed.
- **Severity when active:** hint
- **Automatic fix:** none; repair by hand
- **Guide:** Drop from __future__ import annotations when no annotation needs postponing

## Why

On targets before Python 3.14 or with an unknown minimum, when-needed mode retains imports for quoted and unresolved forward references, TYPE_CHECKING, runtime annotation inspection, decorated definitions and complex annotation expressions. This includes dataclasses and Pydantic models: decoration can consume annotations, so modern decorated code may receive no hint even when removal happens to work. Other cases get a conservative review hint, not proof of safe removal. Declared Python 3.14+ targets are handled by TYP001.

## Bad

```python
from __future__ import annotations

def count(value: int) -> int:
    return value
```

## Good

```python
def count(value: int) -> int:
    return value
```

## How to fix

Review whether postponement is part of the module's runtime contract, then remove unnecessary boilerplate and verify types and behavior. On Python 3.12/3.13, an annotations future import is appropriate when the chosen public-first order uses forward references; LAY004 preserves eager dependencies when the import is absent. Keep the import if it serves a real purpose; annotate a justified exception if required. Self is only an alternative for methods whose return contract follows the receiver's subclass, such as returning self or constructing cls; a matching class-name annotation alone is insufficient. No Self rewrite is suggested automatically.
