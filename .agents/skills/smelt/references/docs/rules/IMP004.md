# IMP004 imports/prefer-package-import

Prefer an existing package re-export over an implementation import.

- **Category:** imports
- **Activation:** explicit — Enable by rule setting or --select; configurable when style or a package override lists third_party_reexports.
- **Severity when active:** hint
- **Automatic fix:** some findings carry a fix
- **Guide:** Import names through the package that re-exports them, not their implementation module

## Why

Importing supported names from a common package keeps callers independent of implementation paths and allows related imports to be combined. This opt-in hint requires every name in a from-import to have an unconditional, direct, same-named public re-export in an analyzed ancestor __init__.py. The nearest eligible package is suggested. Static __all__ is respected. Production imports inside that package are excluded to avoid routing its own implementation through its initializer. Discovered tests and conftest.py are checked, including configured test roots inside the package. Test-quality exclusions do not exempt imports; project exclusions and normal suppressions apply. Imports in package initializers also stay unchanged. Conditional, rebound, private, star and dynamic exports, re-export chains and module imports are outside this check. Installed packages listed in third_party_reexports are read from the interpreter Smelt runs in, without importing them: stubs take precedence, star imports count when the target declares a static __all__, and names imported under TYPE_CHECKING count when a module __getattr__ serves them and __all__ lists them. Other third-party packages, and listed packages Smelt cannot find, are not checked.

## Bad

```python
# app/observation/__init__.py exports Observe and Snapshot
# app/client.py
from app.observation import Observe
from app.observation.models import Snapshot
```

## Good

```python
# app/client.py
from app.observation import Observe, Snapshot
# style: {third_party_reexports: [fastapi]}
from fastapi import APIRouter
```

## How to fix

Use the suggested package import and combine it with an existing import there when both are in the same scope and guard. Preserve aliases, comments and relative/absolute import policy. Review initializer side effects and dependency cycles. No exports are created and analyzed code is never executed. check --fix --unsafe-fixes imports from the package, merging into an import of it in the same block when neither statement carries a comment.
