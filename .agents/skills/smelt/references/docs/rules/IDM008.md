# IDM008 idioms/loop-invariant-collection

A membership lookup set is rebuilt in a loop from stable immutable inputs.

- **Category:** idioms
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint
- **Automatic fix:** none; repair by hand
- **Guide:** Build a lookup set from stable inputs once, outside the loop

## Why

Repeated lookup-set construction can turn one validation pass into quadratic work and obscure a shared domain set. This opt-in review requires positive, file-local evidence: homogeneous immutable tuple literals, tuple[T, ...] annotations, or tuple fields of standard-library frozen dataclasses declared in the same module. Scalar projections may read directly declared fields of those frozen records. Annotations are assumed to describe standard builtin values and these concrete record types; runtime subclass overrides or frozen-state bypasses are not proved safe. This is not a runtime immutability proof. Records with bases, extra decorators or custom attribute access are excluded, as are descriptors, unknown fields and imported record types. Minimum snapshot evidence is a local @dataclass(frozen=True) record with a plain id: str field and a tuple[Record, ...] input; the outer iteration must also be a known tuple. The original Harnessed example uses Pydantic dataclasses and Annotated fields, which this initial implementation deliberately does not infer. Only direct for loops with a simple name target in functions or ordinary methods are reviewed; while and async loops are not inferred. The body must consist of passive scalar/tuple expressions, simple local assignments, conditionals, returns, breaks/continues or literal builtin error raises. Unknown calls, mutation through aliases, properties, nested loops/scopes, await/yield and uncertain operations make it stay quiet. A single-generator set comprehension must produce known builtin scalar values and appear on the right of in/not in. Equivalent projections are grouped per loop, including renamed comprehension variables. Tests are ignored.

## Bad

```python
def validate(wanted: tuple[str, ...], available: tuple[str, ...]):
    for name in wanted:
        if name not in {item for item in available}:
            raise ValueError("Unknown name")
```

## Good

```python
def validate(wanted: tuple[str, ...], available: tuple[str, ...]):
    # Evaluate at the first required check if earlier evaluation matters.
    names = set(available)
    for name in wanted:
        if name not in names:
            raise ValueError("Unknown name")
```

## How to fix

Review computing the lookup set once and reusing it. Preserve the empty-loop case, guards, exception timing and evaluation order: moving construction before a loop or guard can evaluate code that previously never ran. Keep lazy initialization at the first required check when necessary. No automatic hoisting is provided. Enable rules: {idioms/loop-invariant-collection: hint}, or select IDM008.
