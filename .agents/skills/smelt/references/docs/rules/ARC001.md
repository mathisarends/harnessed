# ARC001 architecture/layer-boundary

A layer imports a layer outside its `may_depend_on` allowlist.

- **Category:** architecture
- **Activation:** explicit — Enable by rule setting or --select; requires that architecture.layers defines layer dependencies.
- **Severity when active:** error
- **Automatic fix:** none; repair by hand
- **Guide:** Import only from layers this layer may depend on; reach other layers through a port wired in the composition root

## Why

Layers only stay replaceable and testable when dependencies point in one direction. An application service that imports infrastructure cannot be used without the database, HTTP client or framework behind it. With architecture.import_graph.transitive, the allowlist also applies to every reachable layer, including paths through allowed layers and helpers. Indirect findings include a shortest import chain.

## Bad

```python
# voice/application/session.py
from gateway.features.voice.infra.sql import SqlVoiceSessionRepository
```

## Good

```python
# voice/application/session.py
from gateway.features.voice.application.ports import VoiceSessionRepository

# gateway/bootstrap.py wires SqlVoiceSessionRepository to the port
```

## How to fix

Depend on an abstraction (a port) owned by the importing layer or an allowed layer, and wire the concrete implementation in the composition root.

## Config

- `architecture.layers.<layer>.may_depend_on`
- `architecture.layers.<layer>.modules`
- `architecture.import_graph.transitive`
- `architecture.import_graph.type_checking`

Explain it in the terminal with `smelt explain ARC001`.
