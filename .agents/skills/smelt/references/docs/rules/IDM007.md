# IDM007 idioms/duplicate-narrowing-assert

Several methods of a class assert the same narrowing of a self attribute.

- **Category:** idioms
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** warning
- **Automatic fix:** none; repair by hand
- **Guide:** Set required attributes at construction instead of asserting them in every method

## Why

assert self._stack is not None in one method narrows a type for the checker. When several methods of the class repeat it, the attribute is optional in its type but required after setup, and every caller depends on a check that python -O removes. This opt-in review reports, once per class and expression, an assert of self.<attribute> is not None or isinstance(self.<attribute>, ...) that appears in at least two methods of the same class, including each operand of an and. Asserts in nested functions belong to that function, static methods are skipped and tests are not checked. Unlike a blanket assert ban, single local narrowings stay valid.

## Bad

```python
class Tabs:
    def open(self, url: str) -> None:
        assert self._stack is not None
        self._stack.push(url)

    def close(self) -> None:
        assert self._stack is not None
        self._stack.pop()
```

## Good

```python
class Tabs:
    @property
    def stack(self) -> Stack:
        if self._stack is None:
            raise RuntimeError("Tabs used before start()")
        return self._stack

    def open(self, url: str) -> None:
        self.stack.push(url)
```

## How to fix

Make the attribute required by constructing it before the object is used, or read it through one property or accessor that raises an error naming the missing setup step. No automatic rewrite is performed. Enable rules: {idioms/duplicate-narrowing-assert: warning}, or select IDM007.
