# CPX002 complexity/inline-call-argument

An awaited result, eager comprehension or builtin reduction is passed directly as a call argument.

- **Category:** complexity
- **Activation:** explicit — Enable by rule setting or --select; configurable when style or a package override sets call_argument_kinds.
- **Severity when active:** hint
- **Automatic fix:** none; repair by hand
- **Guide:** Bind awaited results, comprehensions and builtin reductions to a local name before passing them as arguments

## Why

Naming an intermediate value before passing it on separates the suspension point or collection transformation from the construction or call that consumes it, and gives the value a name in tracebacks and debuggers. This opt-in syntax review reports a direct positional or named keyword argument of a call in production code that is one of the kinds in call_argument_kinds (all by default): await (an await expression, including nested forms such as await f(await g())), comprehension (a list, set or dict comprehension, even when CPX006 accepts its internal logic) or aggregate (an unshadowed builtin all, any, max, min, sorted or sum reducing a generator expression; the whole reduction is named and the generator stays lazy). It applies to any call without inferring constructors or runtime types and reports each argument once. Plain awaits, return await, named values, other calls and attribute reads, generator expressions passed directly, starred arguments and values nested inside another argument expression are outside scope. Arguments within lambdas, comprehensions, conditional expressions, boolean operators, while conditions, chained comparisons and assert messages are skipped because extraction would change when or how often they run. Tests are excluded.

## Bad

```python
async def to_response(browser, result):
    return Response(
        text=await browser.clipboard.read(),
        users=[to_user(user) for user in result.users],
        active=sum(user.active for user in result.users),
    )
```

## Good

```python
async def to_response(browser, result):
    text = await browser.clipboard.read()
    users = [to_user(user) for user in result.users]
    active = sum(user.active for user in result.users)
    return Response(text=text, users=users, active=active)
```

## How to fix

Assign the value to a local variable in the statement before the call and pass that variable; a named keyword supplies a suggested variable name. Preserve the callable lookup, argument evaluation order, guards and suspension points: moving an argument before the call can evaluate it before earlier arguments or the callable itself. Do not eagerly materialize generator expressions. No automatic rewrite is performed. Enable rules: {complexity/inline-call-argument: hint}, select CPX002, or set call_argument_kinds under style or in a style override, which also narrows the review to that scope. Reasoned inline suppressions are supported.

## Config

- `rules`
- `style.call_argument_kinds`
- `style.overrides`

Explain it in the terminal with `smelt explain CPX002`.
