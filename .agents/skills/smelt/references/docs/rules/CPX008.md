# CPX008 complexity/inline-constructor-receiver

A method is called directly on a newly constructed instance.

- **Category:** complexity
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint
- **Automatic fix:** none; repair by hand
- **Guide:** Bind a newly constructed instance to a name before calling methods on it

## Why

Naming the instance on its own line makes it easier to distinguish construction from the operation that follows. This opt-in review checks direct method calls used as the whole value of an assignment, return or expression statement, including an awaited call. It recognizes unshadowed top-level class declarations and unshadowed imports whose final name starts with a capital letter (ignoring leading underscores). The import convention is a heuristic and can also match a callable with a class-like name. The rule skips files with wildcard imports. Bare builtins, unresolved names, lowercase factory imports, chains of method calls, nested expressions and test files are outside its scope.

## Bad

```python
from plugins import PointerTools

pointer = PointerTools().tool(
    PointerTools.drag_at,
    description="Press, move, release.",
)
```

## Good

```python
from plugins import PointerTools

pointer_tools = PointerTools()
pointer = pointer_tools.tool(
    PointerTools.drag_at,
    description="Press, move, release.",
)
```

## How to fix

Assign the constructor call to a descriptive variable before the statement and use that variable as the method receiver. Review whether keeping the instance bound affects its lifetime. No automatic rewrite is performed. Enable rules: {complexity/inline-constructor-receiver: warning} globally or in a package override, or select CPX008.
