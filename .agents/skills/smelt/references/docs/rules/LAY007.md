# LAY007 layout/file-name-convention

A YAML or Compose filename differs from the project's canonical spelling.

- **Category:** layout
- **Activation:** explicit — Enable by rule setting or --select; requires that style.file_naming selects a canonical YAML extension or Compose basename.
- **Severity when active:** error
- **Automatic fix:** none; repair by hand
- **Guide:** Use the project's canonical YAML and Compose file names

## Why

Choose spellings once in style.file_naming to keep configuration filenames consistent. yaml_extension (yaml or yml) checks lowercase .yaml and .yml filenames below the directory containing smelt.yml, including the Smelt configuration itself, Compose files and hidden directories such as .github. compose_basename (compose or docker-compose) recognizes compose.yaml, docker-compose.yml and dotted variants such as docker-compose.override.yaml anywhere below the project root; variant suffixes are preserved. A file violating both options gets one finding with the fully corrected path. Custom filenames such as stack.yaml are not classified by content. Project exclusions and tool/cache directories are skipped. No YAML contents are parsed, and an omitted option permits either spelling even with --select ALL.

## Bad

```yaml
# With yaml_extension: yaml, compose_basename: compose
# settings.yml
# docker-compose.override.yaml
```

## Good

```yaml
# With yaml_extension: yaml, compose_basename: compose
# settings.yaml
# compose.override.yaml
```

## How to fix

Rename the file to the expected path and update references to its old name, including CI, scripts, docker compose -f arguments and extends entries. Check for existing destination files before renaming. No file or reference is changed automatically. Use a reasoned project.exclude or ignore.paths entry for filenames required by another tool.

## Config

- `style.file_naming.yaml_extension`
- `style.file_naming.compose_basename`
- `project.exclude`
- `ignore`

Explain it in the terminal with `smelt explain LAY007`.
