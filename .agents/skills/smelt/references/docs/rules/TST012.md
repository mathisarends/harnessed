# TST012 tests/missing-mirror-test

A source module with behaviour has no test at its mirrored path.

- **Category:** tests
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** warning
- **Automatic fix:** none; repair by hand
- **Guide:** Add a test at the mirrored path for every module with behavior

## Why

With `layout: mirror`, the mirrored path is where readers and agents look for the tests of a module. TST001 keeps existing tests in place, but a module added without a test goes unnoticed. This opt-in review reports modules that define at least one function or method with a real body and have no test file at the path tests.mirror gives them, or, with tests.mirror_suffixes, no topic test next to it. Packages (`__init__.py`), `__main__.py` and modules that only declare data, constants, protocols or abstract stubs are not reported. A module may still be covered by behaviour, integration or package tests elsewhere; the rule does not follow imports or measure coverage.

## Bad

```python
app/billing/invoice.py         # def total(...) ...
tests/billing/                 # no test_invoice.py
```

## Good

```python
app/billing/invoice.py
tests/billing/test_invoice.py
```

## How to fix

Add the mirrored test file with tests of the module's behaviour. When another test deliberately covers the module, mark the module with `# smelt: ignore-file[TST012] -- <reason>`, or turn the rule off for a package in its `rules`. In an existing project, record current gaps with `smelt adopt` so changed checks report only new modules. Enable rules: {tests/missing-mirror-test: warning} or select TST012.

## Config

- `rules`
- `tests.layout`
- `tests.mirror`
- `tests.mirror_suffixes`
- `project.test_roots`

Explain it in the terminal with `smelt explain TST012`.
