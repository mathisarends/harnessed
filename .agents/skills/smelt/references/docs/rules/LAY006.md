# LAY006 layout/callee-before-caller

A direct caller appears after same-visibility helpers it calls.

- **Category:** layout
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint
- **Automatic fix:** some findings carry a fix
- **Guide:** Place a caller before the helpers it calls within the same visibility group

## Why

A step-down reading order introduces a higher-level operation before its lower-level helpers. This opt-in review covers stable undecorated top-level sync/async functions and direct methods on undecorated classes without bases. It resolves direct same-module names and receiver.method calls, excludes shadowed bindings, nested scopes, comprehensions, dunder methods and recursive call components, and respects definition-time parameter/return dependencies. Only same-visibility pairs are reviewed so LAY004's public-first categories retain precedence. Dynamic lookup, inherited APIs and general call graphs are not inferred. This is a reading convention, not a correctness check.

## Bad

```python
def parse():
    return 1

def load():
    return parse()
```

## Good

```python
def load():
    return parse()

def parse():
    return 1
```

## How to fix

Review placing the caller before its helper within the same public/private group. Preserve defaults, decorators, annotations, rebinding and execution barriers. check --fix moves the caller, with the comment lines directly above it, before its earliest helper; it leaves callers whose defaults or annotations read names bound by the definitions they would pass. LAY004 independently handles public-first ordering and its bounded fixer. Enable rules: {layout/callee-before-caller: hint} or select LAY006; package overrides and reasoned suppressions apply.
