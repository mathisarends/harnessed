# CPX007 complexity/excess-constructor-decisions

A constructor contains more decisions than the configured limit.

- **Category:** complexity
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint
- **Automatic fix:** none; repair by hand
- **Guide:** Keep constructor decisions within the limit; move normalization into a named function

## Why

Normalization, validation and derivation become easier to understand when named separately from object initialization. This opt-in review counts if, for/async for, while, try/try-star, match, raise, comprehension and conditional-expression nodes in __init__ and __post_init__ methods. Each comprehension counts once, in addition to any conditional expressions inside it; its generator clauses are not counted separately. Nested function, lambda and class definitions are skipped. Helper calls count zero. A single guard with raise counts two, so it remains valid at the default limit of 2. Only production source is checked. __new__ and other validation methods are outside the scope. This metric is advice, not proof that a constructor needs refactoring.

## Bad

```python
class Client:
    def __init__(self, values):
        for value in values:
            if not value.ready:
                raise ValueError('not ready')
        self.values = values
```

## Good

```python
class Client:
    def __init__(self, values):
        self.values = validate_values(values)
```

## How to fix

Move a cohesive normalization or validation step into a named function or classmethod and assign its result. Preserve evaluation order, exceptions and initialization side effects. Do not extract arbitrary fragments merely to lower a count. No automatic rewrite is performed. Enable rules: {complexity/excess-constructor-decisions: hint} or select CPX007; set max on the entry, in the root or a style override's rules. The limit defaults to 2; 0 forbids any counted decision. Reasoned suppressions and package off overrides are supported.

## Config

- `rules`
- `style.overrides`

Explain it in the terminal with `smelt explain CPX007`.
