# ARC003 architecture/forbidden-third-party-import

A layer imports a third-party package its `third_party` policy does not allow.

- **Category:** architecture
- **Activation:** explicit — Enable by rule setting or --select; requires that a layer's third_party policy restricts dependencies.
- **Severity when active:** error
- **Automatic fix:** none; repair by hand
- **Guide:** Import a third-party package only in layers whose third_party policy allows it

## Why

Inner layers should not know about frameworks, drivers or SDKs. Keeping them out makes the core portable and cheap to test. With architecture.import_graph.transitive, the importing layer's policy also applies to packages reached through project modules, such as domain -> shared.utils -> sqlalchemy. A shortest chain includes each import's source line. External packages are leaves: their own source is not scanned. Standard-library imports remain allowed.

## Bad

```python
# voice/domain/session.py
from sqlalchemy.orm import Mapped
```

## Good

```python
# voice/domain/session.py
from dataclasses import dataclass
```

## How to fix

Move the code that needs the package into a layer that allows it and expose it through a port, or extend the layer's `third_party` policy.

## Config

- `architecture.layers.<layer>.third_party.default`
- `architecture.layers.<layer>.third_party.allow`
- `architecture.layers.<layer>.third_party.deny`
- `architecture.import_graph.transitive`
- `architecture.import_graph.type_checking`

Explain it in the terminal with `smelt explain ARC003`.
