# MOD002 modeling/forbidden-base-class-affix

A class definition carries a Base prefix or suffix instead of a responsibility.

- **Category:** modeling
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** error
- **Automatic fix:** none; repair by hand
- **Guide:** Name classes after their responsibility, without a Base prefix or suffix

## Why

BaseService and MessageBase name a position in an inheritance hierarchy rather than the abstraction's responsibility. A responsibility-based name such as Service keeps that implementation choice out of the name. The affix does not itself create dependency coupling, and inheritance can be intentional, so this is an opt-in naming convention rather than a correctness check or an inheritance ban. It checks all class definitions in production modules, including private, nested and local classes, without inferring whether they have subclasses. After leading underscores, a prefix Base must be the whole name or be followed by an uppercase letter or underscore; a suffix Base must follow a non-empty name. Baseline, Baseball, Database and Base64 remain valid. Imports, aliases, base-class expressions, function names and test files are outside scope; inheriting from an imported BaseModel is allowed.

## Bad

```python
class BaseRepository:
    ...

class _MessageBase:
    ...

class SqlRepository(BaseRepository):
    ...
```

## Good

```python
class Repository:
    ...

class Message:
    ...

class SqlRepository(Repository):
    ...
```

## How to fix

Choose a name describing the class's responsibility or contract, then update references and deliberate exports. Preserve inheritance where it serves the design. A more specific package rule can disable the convention for compatibility, or a reasoned suppression can preserve a published name. No symbols are renamed automatically. Enable with rules: {modeling/forbidden-base-class-affix: error}, globally or in a style override, or --select MOD002.

## Config

- `rules`
- `style.overrides`

Explain it in the terminal with `smelt explain MOD002`.
