# LAY010 layout/reexport-only-module

An ordinary module consists entirely of explicit re-exports.

- **Category:** layout
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint
- **Automatic fix:** none; repair by hand
- **Guide:** Import from the defining module or the package API; do not add re-export-only modules

## Why

A module that only forwards names adds another import path to maintain. This opt-in hint looks for direct imports marked by same-name aliases or a single literal __all__ list or tuple covering every import binding. A module docstring and future imports are allowed. The check is limited to ordinary production modules with distinct, unambiguous bindings. Package initializers, star imports, rebinding, conditional imports and dynamic export declarations fall outside this source pattern.

## Bad

```python
# app/events_api.py
from .events import Event as Event

# app/client.py
from .events_api import Event
```

## Good

```python
# app/client.py
from .events import Event
```

## How to fix

Review moving callers to the defining module or an intentional package API. A supported compatibility path can use a reasoned suppression. Check published import paths, side effects and cycles before removing a forwarding module. This is a read-only review.
