# VIS008 visibility/reexport-convention

A package initializer spells a re-export against its configured convention.

- **Category:** visibility
- **Activation:** explicit — Enable by rule setting or --select; configurable when style or a package override sets reexports to all or alias.
- **Severity when active:** warning
- **Automatic fix:** some findings carry a fix
- **Guide:** Follow the package's re-export convention in __init__.py

## Why

Use style.reexports to give package APIs a consistent spelling. all reports explicit same-name import aliases and uses __all__ for the public export list. alias reports ordinary imports named by a statically resolved __all__ when a same-name alias can mark the re-export. Existing aliases can coexist with an intentional runtime export list. The rule considers unique, direct import bindings in production __init__.py files. Real renames, dotted module imports, guarded or rebound names and star imports are outside its inference. Selecting the rule without a style uses all.

## Bad

```python
# style: {reexports: all}
# app/events/__init__.py
from .models import Event as Event
```

## Good

```python
# app/events/__init__.py
from .models import Event

__all__ = ["Event"]
```

## How to fix

With all, use a plain import and include the name in __all__ if it belongs to the public API. With alias, use a same-name alias such as Event as Event and preserve an intentional runtime export list. For a package that needs either spelling, set reexports to allow in a style override with a reason. check --fix adds the same-name alias, or drops it where __all__ already lists the name; adding the name to __all__, or creating __all__, changes what star imports export and needs --unsafe-fixes. A dynamic __all__ is left for a manual edit.

## Config

- `rules`
- `style.reexports`
- `style.overrides`
