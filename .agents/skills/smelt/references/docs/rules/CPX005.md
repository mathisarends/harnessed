# CPX005 complexity/forbidden-nested-conditional

A conditional expression directly contains another result conditional.

- **Category:** complexity
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint
- **Automatic fix:** none; repair by hand
- **Guide:** Write nested decisions as if/elif or match statements, not nested conditional expressions

## Why

Nested conditional expressions hide a multi-branch decision inside one expression. This opt-in style review reports a conditional whose body or else branch is another conditional expression, once at the outermost expression in each directly connected chain. Conditionals inside tests, calls, lambdas or comprehensions are separate expressions; their presence alone does not make the enclosing conditional nested. Simple fallbacks and independent conditionals remain valid. Only production source is checked; no type or runtime inference is used.

## Bad

```python
status = OK if completed else TIMEOUT if timed_out else ERROR
```

## Good

```python
if completed:
    status = OK
elif timed_out:
    status = TIMEOUT
else:
    status = ERROR
```

## How to fix

Use explicit if/elif or match statements. Preserve branch order, precedence and lazy evaluation; an eagerly evaluated dictionary can change behavior. No automatic rewrite is performed. Enable rules: {complexity/forbidden-nested-conditional: hint}, or select CPX005. Package overrides and reasoned suppressions are supported.

## Config

- `rules`
- `style.overrides`

Explain it in the terminal with `smelt explain CPX005`.
