# MOD006 modeling/missing-dataclass-option

A dataclass does not set an option its package requires.

- **Category:** modeling
- **Activation:** explicit — Enable by rule setting or --select; requires that style or a package override sets dataclass_options, including [].
- **Severity when active:** warning
- **Automatic fix:** some findings carry a fix
- **Guide:** Set the dataclass options the package requires

## Why

Whether a dataclass is frozen, uses slots or takes keyword-only arguments changes how callers may use it, yet codebases drift between @dataclass, @dataclass(frozen=True) and @dataclass(frozen=True, slots=True) without anyone being able to tell which deviations are deliberate. A style override lists dataclass_options, any of frozen, slots and kw_only, and every production @dataclass in the package must set each of them to True. An option that is missing or explicitly False is reported; a non-literal value is not judged. Missing slots is not reported when a base class comes from outside the project, such as a third-party or builtin class without __slots__, because slots save nothing there; bases from abc and typing still count. It is also not reported for classes with a functools.cached_property, which needs an instance __dict__. Nested packages can set their own list, and [] lifts the requirement. Tests are not checked.

## Bad

```python
@dataclass(frozen=True)
class Policy:
    timeout_seconds: float
```

## Good

```python
@dataclass(frozen=True, slots=True)
class Policy:
    timeout_seconds: float
```

## How to fix

Add the missing options to the decorator. A dataclass that must stay mutable or unslotted keeps a reasoned suppression, or lives in a package whose contract sets its own dataclass_options. check --fix --unsafe-fixes sets the missing options to True, unless the decorator passes **options. Enable it for the project with style: {dataclass_options: [frozen, slots]}, or for one package with the same option in a style override.

## Config

- `style.dataclass_options`
- `style.overrides`

Explain it in the terminal with `smelt explain MOD006`.
