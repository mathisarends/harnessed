# TST013 tests/missing-skip-reason

A test is skipped, expected to fail or rerun without a tracked reason.

- **Category:** tests
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** warning
- **Automatic fix:** none; repair by hand
- **Guide:** Give every skip, xfail and rerun marker a reason that references an issue

## Why

Switching a failing test off is quicker than fixing it, and without a trace of why, the skip stays long after its cause is gone. This opt-in review reports pytest.mark.skip, skipif, xfail and flaky markers, pytest.skip and pytest.xfail calls, unittest.skip, skipIf, skipUnless and expectedFailure, and the flaky and pytest-rerunfailures flaky decorators, wherever they appear in analyzed test modules: as decorators, pytestmark values, pytest.param marks or markers added in conftest.py hooks. A quarantine needs a reason that matches tests.skip_reason_pattern, a Rust regular expression that matches an issue reference or a link by default, in its reason argument or in a comment on its line or directly above. An environment limit only needs a non-empty reason: skipif and xfail with a runtime condition, a strict xfail, and skip or xfail calls inside an if branch or except handler. Literal conditions such as True are not an environment limit. A reason that is not a string literal is accepted because its text is unknown. pytest.importorskip is a dependency check and is not reported. Per-test timeouts belong to tests/unbounded-wait and are out of scope. Test-quality exclusions apply.

## Bad

```python
import pytest

@pytest.mark.skip
def test_sync(): ...

@pytest.mark.flaky(reruns=3)
def test_stream(): ...
```

## Good

```python
import sys

import pytest

@pytest.mark.skip(reason="#123: the sync API returns stale pages")
def test_sync(): ...

@pytest.mark.skipif(sys.platform == "win32", reason="needs POSIX signals")
def test_signals(): ...
```

## How to fix

Fix the test where possible. Otherwise give a quarantine a tracked reason such as reason="#123: <why>", or a comment that references the issue, and name the environment limit in the reason of a conditional skip. Set tests.skip_reason_pattern to your tracker's references, for example 'PROJ-\d+'. No source is rewritten. Enable rules: {tests/missing-skip-reason: warning} or select TST013.

## Config

- `rules`
- `tests.skip_reason_pattern`
- `tests.quality_exclude`

Explain it in the terminal with `smelt explain TST013`.
