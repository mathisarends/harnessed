# IMP003 imports/forbidden-import-style

An import does not follow the package's declared relative/absolute style.

- **Category:** imports
- **Activation:** explicit — Enable by rule setting or --select; requires that style or a package override sets imports.
- **Severity when active:** error
- **Automatic fix:** some findings carry a fix
- **Guide:** Follow the package's relative/absolute import style

## Why

A predictable import style makes ownership easier to read. With relative style and max_relative_level: 1, local imports use one dot; parent and cross-root imports stay absolute. Deeper relative imports can be explicitly allowed. The closest style override supplies the style, else style.imports. No style is enforced without one, and this rule never changes bindings.

## Bad

```python
# app/storage/service.py, relative style with maximum 1
from app.storage.models import Record
from ..domain import Entity
```

## Good

```python
# app/storage/service.py
from .models import Record
from app.domain import Entity
```

## How to fix

Use a relative import within the configured dot limit, otherwise use an absolute import. Preserve aliases and update references if converting an import statement changes its binding. check --fix rewrites the module of a from-import, which keeps every binding; a plain import statement is left for a manual edit.

## Config

- `style.imports`
- `style.overrides`
- `architecture.import_graph.type_checking`
