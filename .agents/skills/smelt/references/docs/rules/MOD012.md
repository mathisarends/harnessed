# MOD012 modeling/parallel-record-fields

Stored sequence fields of one instance are paired by position.

- **Category:** modeling
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint
- **Automatic fix:** none; repair by hand
- **Guide:** Store one sequence of named records instead of parallel sequence fields

## Why

Parallel stored sequences leave their record relationship implicit: every constructor and transformation must preserve matching positions. zip(strict=True) checks lengths but cannot check the right pairing. This opt-in design review groups zip calls over at least two distinct sequence fields on the same instance, once per class and field group, with declaration and zip locations. It checks directly declared class annotations of list, tuple, Sequence and MutableSequence, including typing spellings, quoted annotations and module/import aliases. Preceding unconditional local aliases assigned once from a receiver field are supported. Only undecorated instance methods are inspected. Rebound names, starred arguments, inherited/untyped fields, ClassVar, nested functions and unknown types are skipped. Local sequences and different receivers remain valid. Tests are ignored. The rule cannot establish that the fields form a domain record: intentional column-oriented or numerical storage is valid and can use a reasoned suppression at the reported zip site.

## Bad

```python
class Layout:
    models: tuple[type, ...]
    fields: tuple[tuple[str, ...], ...]

    def split(self):
        for model, names in zip(self.models, self.fields, strict=True):
            yield model, names
```

## Good

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Binding:
    model: type
    names: tuple[str, ...]

class Layout:
    bindings: tuple[Binding, ...]

    def split(self):
        for binding in self.bindings:
            yield binding.model, binding.names

class Columns:
    x: list[float]
    y: list[float]

    def points(self):
        # smelt: ignore[MOD012] -- deliberate numerical column storage
        return zip(self.x, self.y, strict=True)
```

## How to fix

Review whether these fields model one logical record. If so, store one sequence of named records and update construction and consumers together. Preserve length validation and iteration order. Deliberate column storage may retain a reasoned suppression. No automatic rewrite or correctness claim is made. Enable rules: {modeling/parallel-record-fields: hint}, or select MOD012.
