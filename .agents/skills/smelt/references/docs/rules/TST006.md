# TST006 tests/missing-outcome-check

A collected test has no recognized explicit outcome assertion.

- **Category:** tests
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** warning
- **Automatic fix:** none; repair by hand
- **Guide:** Assert a concrete outcome in every test

## Why

A test that merely calls production code can pass when its result is wrong. This opt-in syntactic check accepts assert (except literal assert True), pytest.raises/warns/deprecated_call, unittest.TestCase assertions, known Mock/AsyncMock interaction assertion methods, awaited typed Event.wait observations bounded by wait_for or timeout contexts that raise on expiry, and configured qualified helpers. A move_on_after scope or a configured timeout helper alone does not establish outcome evidence. Mock receivers come from recognized constructors, aliases, patch results or explicit fixture annotations, never arbitrary assert_* method names. It also follows one direct call to an unambiguous, undecorated, non-generator helper in the same file, including nested helpers and async helpers explicitly awaited or passed to asyncio.run. Uncalled definitions, unexecuted coroutines, imported helper bodies, fixture execution, callbacks and further helper calls are not inferred. Possibly swallowed helper assertions supply no evidence; known raising timeout contexts retain it. It neither proves assertions execute nor judges their strength; a frozen scheduler clock can also defeat a timeout. Positive validation/smoke tests can be intentional exceptions. Checked inline Python subprocesses using an unshadowed sys.executable and literal or locally bound script text can provide direct top-level assert evidence. Dynamic scripts, files, optimized Python, shell commands and unchecked exits remain unknown; no analyzed code is executed.

## Bad

```python
def test_deactivate():
    deactivate_user(1)
```

## Good

```python
def test_deactivate():
    user = deactivate_user(1)
    assert user.status == 'inactive'
```

## How to fix

Assert a concrete result or observable state, check the expected exception/warning, or configure a known assertion helper. Use a reasoned exception for deliberate smoke/interaction tests. Do not add a meaningless assertion to silence the finding. helper_review gives call locations and known reasons for missing evidence: imported bodies, unexecuted local coroutines, possible swallowing, or no recognized evidence within one hop. These explain an inference boundary, not proof that a helper contains no assertions.
